# Structured Travel Itinerary

This small Python program asks for distinct source and destination cities,
uses Google Gemini to plan the trip from its own general knowledge, and prints
only a Pydantic-validated JSON itinerary.

The Gemini request uses `response_mime_type="application/json"` together with
the JSON Schema generated by the `TravelItinerary` Pydantic class. It uses
`response_json_schema` so Pydantic's `additionalProperties: false` constraints
are preserved rather than converted to Gemini's older OpenAPI schema format.

The source city is planning context rather than an output field because the
requested schema contains only `destination`, `trip_duration_days`,
`budget_category`, `top_attractions`, and `daily_plan`.

## Run it

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export GEMINI_API_KEY="your-api-key"
python main.py
```

Create a Gemini API key in
[Google AI Studio](https://aistudio.google.com/app/apikey). Optionally set
`GEMINI_MODEL` to another Gemini model that supports structured output. It
defaults to `gemini-2.5-flash`.

The program prompts for both cities after it starts. It uses no live travel
data, so details such as prices, hours, availability, and weather should be
verified separately before travel.

## Run the tests

```bash
python -m unittest -v
```

The tests mock the API response, so they do not make network calls or consume
API quota.
